# Changelog

## 0.3.2

- Ручные команды `start_backup`, `stop_generator` и `reset_recovery` теперь
  поступают непосредственно в App через `hassio.app_stdin`; HA `input_button`
  больше не создаются и не требуются.
- Разрешение автоматического ввода резерва перенесено из
  `input_boolean.automatic_generator_transfer` во внутренний persistent-журнал
  App. Новая установка начинается с АВР `OFF`.
- Добавлены stdin-команды `automatic_transfer_on` и
  `automatic_transfer_off`. Изменение сохраняется сразу и переживает restart.
- Удалены необязательные HA-проекции статуса и сессии. Текущая фаза, источник,
  состояния GC/TPC и положение АВР записываются в журнал App.
- Energy ATS больше не зависит от пользовательских helper-ов в `energy.yaml`.

## 0.3.1

- Реализация приведена в соответствие с прошедшим peer review документом
  `docs/REQUIREMENTS_RU.md`; сценарии ES, TPC и GC закреплены тестами.
- Power Transfer теперь раздельно хранит логический `actual_source` и
  физический `actual_path`: Grid path может питаться от Grid или МАП, а явная
  цель `BATTERY` приводит схему в отдельный Battery path с отключённым Grid.
- Добавлены подтверждаемые переходы Grid/Battery/Generator во всех разрешённых
  направлениях и безопасная обработка изменения цели во время движения
  контакторов.
- Возврат Grid во время автоматического запуска отменяет ввод генератора под
  нагрузку; повторный провал Grid во время возврата или cooldown переиспользует
  уже готовый двигатель только после завершения безопасного силового шага.
- Внешняя остановка без Grid и ручная остановка управляемой сессии сохраняют
  подавление АВР до возврата Grid либо новой ручной команды запуска.
- Fault любого Generator Controller блокирует новую сессию. Автоматический
  fallback на второй генератор по-прежнему запрещён.
- Оба профиля генераторов используют заслонку холодного запуска при каждом
  управляемом запуске; `ambient_temperature_external` влияет только на время
  прогрева.
- Физическая команда заслонки переименована в
  `choke_to_cold_start`; `choke_to_run` означает рабочее положение двигателя.
- Recovery reset разрешён только после ручного возврата силовой схемы в
  подтверждённый Grid path и остановки обоих генераторов.
## 0.3.0

- Монолитный ATS разделён на `EnergySupervisor`, `PowerTransferController`,
  два `GeneratorController` и `HomeAssistantAdapter`; это по-прежнему один
  процесс без связи контроллеров через HA entities.
- Имена, модели, режимы заслонки, прогрев, start/stop timeout и cooldown
  перенесены из Configuration ATS в читаемые профили двигателей внутри
  `generator_controller.py`.
- Внешняя температура имеет явное имя `ambient_temperature_external`, читается
  Python-адаптером из `sensor.garage_temperature` и не импортируется в ESPHome.
- Внешний/локальный запуск теперь только распознаётся и уведомляется: App не
  захватывает двигатель, не двигает заслонку, не меняет REMOTE и силовую схему;
  внешнее включение REMOTE распознаётся ещё до появления RUNNING.
- Power Transfer допускает генераторную шину только после `ready_for_load` и
  сохраняет подтверждаемый break-before-make для Grid/Generator/МАП.
- Одновременные несовместимые положения Grid/Generator и появление второго
  активного агрегата во время управляемой сессии блокируют автоматику; источник
  сначала изолируется, автоматического захвата второго генератора нет.
- Cooldown принадлежит Generator Controller; двигатель невозможно штатно
  остановить, пока его нагрузка не подтверждённо снята.
- Ручная outage-сессия при стабильном возврате Grid возвращает дом на сеть, но
  сохраняет ручное намерение RUN. После выдержки отправляется напоминание о
  работе без нагрузки; автоматической остановки пока нет.
- Ручная остановка без Grid подавляет новый запуск по АВР до возврата сети
  или новой ручной команды запуска; решение переживает restart.
- При отказе активный источник изолируется, но автоматический fallback A → B
  сознательно отключён до накопления эксплуатационного опыта.
- Добавлен persistent transaction journal с записью pending-команд до
  аппаратного service call. Restart/потеря HA во время операции приводит к
  `RECOVERY_REQUIRED`; устойчивое состояние не изменяется.
- Кратковременное `unknown/unavailable` обязательного датчика замораживает
  автоматы без команд и не стирает последнюю подтверждённую фазу.
- После restart сохранённая steady-state сессия восстанавливает ownership
  только при совпадении журнала с фактическим положением силовой схемы.
- Удалены исторические монолитный `ats_core.py`, policy-wrapper и versioned
  entrypoint-файлы; Git history сохраняет код 0.2.x.
- Runtime запускается напрямую через `main.py`.

## 0.2.5

- Кнопка `Остановить генератор` теперь прерывает любую управляемую процедуру
  запуска/работы резерва и использует безопасный подтверждаемый порядок:
  generator selector -> Grid, подтверждение изоляции, Grid path -> ON,
  cooldown, REMOTE -> OFF.
- Ручная остановка разрешена при `Grid Input Ready = OFF`: это штатно
  возвращает дом в нормальную топологию, а UPS-линия продолжает работу от
  аккумуляторов МАП. Предупреждение о невозможности возврата на Grid удалено;
  автоматический повторный запуск блокируется до возврата сети или новой
  ручной команды запуска.
- Добавлена кнопка `input_button.generator_ats_reset` для выхода из `TERMINAL`
  без перезапуска App. Reset принимается только после снятия Emergency Stop,
  остановки обоих генераторов, снятия обоих REMOTE и подтверждения безопасного
  положения силовой схемы.
- Добавлен optional UI helper `input_text.generator_ats_status` с понятными
  состояниями: запуск, прогрев, переключение, питание от генератора, ручная
  остановка, terminal и другие фазы.
- ATS core обновлён до v1.3; runtime запускается через `main_v125.py`.

## 0.2.4

- Добавлена настройка primary generator и возможность отключить каждый
  генератор отдельно в Configuration App.
- Ручная команда возврата стала глобальным operator abort и могла прерывать
  запуск/прогрев, но ещё требовала доступную Grid. В 0.2.5 эта логика заменена
  безопасной остановкой с поддержкой режима МАП от аккумуляторов.
- Сообщения runtime используют заданные имена генераторов.

## 0.2.3

- Исправлен аварийный fallback при остановке активного генератора под
  нагрузкой: перед запуском второго агрегата ATS снимает REMOTE с отказавшего,
  переводит силовой селектор из GENERATOR и ждёт подтверждений
  `Remote=False`, `SourceGenerator=False`, `HouseGen=False`.
- Резервный генератор теперь всегда запускается и прогревается без нагрузки;
  при неподтверждённой изоляции ATS переходит в terminal и включает Emergency
  Stop, не пытаясь запускать backup.
- Аппаратные команды failover выполняются до HA-уведомлений, поэтому медленный
  notify больше не сокращает фактический timeout запуска второго генератора.
- В режиме `ARMED` теперь логируются изменения всей физической картины, включая
  `ATS=True/False`, даже если текущая фаза state machine не изменилась.

## 0.2.2

- Добавлена отдельная политика заслонки для Generator A / Elemax и
  Generator B / Вепрь: `always`, `temperature` или `never`.
- Текущие безопасные defaults: Elemax = `always`, Вепрь = `temperature`.
- Температурный порог остаётся экспериментальным; неизвестная температура
  в режиме `temperature` приводит к cold start.
- Решение по заслонке и выбранный режим теперь явно записываются в лог запуска.

## 0.2.1

- Исправлены реальные entity_id силовых logical switch:
  `switch.grid_power` и `switch.use_generator_as_power_source`.
- Учтена положительная полярность `switch.grid_power`:
  ON подключает Grid, OFF отключает Grid.
- Добавлен adapter-тест инверсии `grid_power -> grid_disconnected`.

## 0.2.0

- AppDaemon удалён из runtime-архитектуры.
- ATS оформлен как standalone Home Assistant App.
- Добавлен Home Assistant WebSocket client через Supervisor Core proxy.
- Добавлены русские переводы параметров App.
- `armed=false` реализован как жёсткий нижний safety gate.
- В DISARMED режиме выполняется только наблюдение, без ложной симуляции timeout state machine.
- Сохранён и повторно протестирован ATS core v1.1.
- Добавлены adapter/WebSocket tests; всего 29 тестов.
