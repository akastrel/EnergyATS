# Delayed Start и Charge Cycling — EnergyATS 0.7

Нормативное поведение задано в [разделе 25 требований](REQUIREMENTS_RU.md#25-delayed-generator-start-и-long-outage-charge-cycling).

## Как работает

**Delayed Start** позволяет переждать отключение сети на батарее. После обычного `grid_failure_delay` генератор остаётся выключенным, пока батареи хватает. Его запуск начинается при достижении любого из трёх пределов: низкий SoC, малый TTG при разряде или максимальное время ожидания. МАП самостоятельно питает UPS-линию; EnergyATS не управляет отдельным батарейным контактором.

**Charge Cycling** предназначен для длительного отключения. Автоматически запущенный генератор питает дом и заряжает батарею до Target SoC. Затем EnergyATS снимает дом с генератора через TPC, подтверждает снятие нагрузки, выдерживает штатный cooldown и останавливает двигатель. Начинается новый интервал UPS с теми же тремя условиями следующего запуска.

Обе функции включаются независимо. Можно задержать только первый запуск без последующих остановок. Можно разрешить cycling с немедленным первым запуском после обычного `grid_failure_delay` — последующие циклы всё равно ждут батарейных порогов.

**При UPS_ONLY обычная часть дома остаётся без питания.** Работает критическая линия через МАП. Включайте эти функции, если такой режим соответствует вашей задаче.

## Настройки

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `delayed_generator_start_enabled` | `false` | Разрешить задержку первого автоматического запуска |
| `generator_charge_cycle_enabled` | `false` | Разрешить остановку собственных автоматических циклов по заряду |
| `generator_start_soc` | `40` % | Запустить при SoC не выше порога |
| `generator_target_charge_soc` | `80` % | Завершить собственный цикл при SoC не ниже цели |
| `generator_min_ttg_before_start` | `60` мин | Запустить при TTG не выше порога во время разряда |
| `generator_max_start_delay` | `21600` с (6 ч) | Максимум каждого периода ожидания на UPS |

Должно выполняться `0 < Start SoC < Target SoC <= 100`. Неверное соотношение отключает оптимизацию, а обычная ATS-логика продолжает работать. Эти параметры не изменяют зарядный ток или напряжение МАП.

## Батарейные сигналы

| HA entity | Ожидаемый смысл |
|---|---|
| `sensor.ups_battery_charge_level_soc` | Числовой заряд батареи, 0–100 % |
| `sensor.ups_battery_time_remaining_minutes_ttg` | Числовое оставшееся время разряда, **минуты** |
| `binary_sensor.ups_running_on_battery` | `on` — батарея действительно разряжается; `off` — зарядка/поддержание |
| `binary_sensor.ups_ready` | `on` — UPS способна продолжать работу от АКБ; `off` — дальнейшее ожидание недопустимо |

Перед включением убедитесь, что `ups_ready` действительно отражает готовность батареи, включая критическое состояние. Постоянное `on` вместо реального сигнала не обеспечивает отмену задержки при критическом разряде. Entity TTG должен содержать минуты, а не отформатированную строку вида «2 ч 15 мин».

Все четыре входа — мягкие зависимости: их отсутствие не блокирует запуск App или core ATS. При выключенных функциях они не влияют на управление.

Во время ожидания SoC и готовность UPS должны быть достоверными. При разряде также требуется конечный неотрицательный TTG; неизвестный или бесконечный TTG вызывает fail-safe запуск по недостоверности данных. При зарядке/поддержании TTG не участвует в решении, а SoC, готовность UPS и максимальное время ожидания продолжают проверяться.

Отсутствие нового SoC или необходимого TTG более **300 секунд** считается stale. Обновления SoC и TTG учитываются независимо; старый timestamp `last_updated` из HA не становится свежим при restart/reconnect. Это консервативная проверка: если числовой sensor долго не публикует обновлений, функция откажется от экономии топлива. При недостоверном SoC/готовности уже работающий генератор по Target SoC не останавливается.

## Ручные команды и возврат сети

`start_generator` во время ожидания немедленно создаёт ручную сессию. Во время уже активного автоматического цикла команда устанавливает manual override: достижение Target SoC больше не останавливает эту сессию. При запросе во время остановки возобновляется обычный запуск того же двигателя. `stop_generator` завершает активную управляемую сессию по существующим правилам ручной остановки.

Внешние и ранее вручную запущенные генераторы не становятся cycle-owned по одному лишь SoC. Переданный из scheduled exercise генератор также не получает это право автоматически.

Устойчивый возврат Grid завершает outage по обычным правилам, без ожидания Target SoC. Между циклами EnergyATS восстанавливает сетевой ввод, который сам изолировал при завершении цикла. Краткое появление сети не обнуляет прошедшее время ожидания.

## Restart и диагностика

Устойчивое ожидание сохраняет время начала, а действующая сессия — cycle ownership и manual override. После restart проверяются текущие физические и батарейные данные. Перезапуск во время незавершённого transfer/stop или с незавершённой аппаратной командой требует обычного Recovery; автоматического угадывания фазы нет.

В `sensor.energy_ats_status` смотрите `source`, `phase`, `charge_cycle_state`, `delayed_start_reason`, `battery_soc`, `battery_ttg_minutes`, `delayed_start_elapsed_seconds`, `delayed_start_remaining_seconds`, `cycle_session_owned_by_energy_ats`, `session_manual_override`. Причина запуска/завершения также попадает в Logbook. Полный контракт — в [справке entities](ENTITIES_RU.md).
