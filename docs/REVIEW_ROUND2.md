# Повторное ревью первого раунда Energy ATS

База: origin/main, commit 770878642511750ea15f3fb55bfa1a7f5f361760,
версия 0.3.10. Ветка: review/simplify-session-lifecycle.
Совместимость со старыми версиями исключена из требований пользователем.

## Вывод

Ощущение избыточности подтвердилось частично. После изменения политики
ручной outage-сессии осталась целая ветвь длительной работы без нагрузки:
состояние, таймер, предупреждение, настройка и поля журнала. Её удаление
полезнее механического разбиения больших методов.

Текущую трёхуровневую модель ES/TPC/GC сохраняем. Объём кода сам по себе
не доказывает проблему производительности; измерений на оборудовании в рамках
этого ревью не проводилось.

## Принятые решения

1. Удалить MANUAL_GENERATOR_IDLE и всё его обслуживание. Новая сессия
   попадала в возврат только по явному stop_generator или при восстановлении
   Grid после outage. В обоих случаях она должна завершаться остановкой.
   Недостижимая для этих сценариев ветвь продолжительного холостого хода
   больше не нужна. Обычный cooldown остаётся в GC.
2. Удалить manual_idle_warning_seconds из настроек, SupervisorConfig,
   руководства установки и журнала вместе с generator_idle_since и
   idle_warning_sent.
3. Прекратить миграцию returning_to_normal, чтение журнала без общего
   контейнера supervisor и поддержку имени класса EnergyATSApp.
   Неизвестный журнал по-прежнему приводит к RECOVERY_REQUIRED.
   Восстановление устойчивой сессии текущего формата сохраняется.
4. Принимать primary_generator по отображаемому имени Elemax/Вепрь.
   Значения A/B больше не преобразуются автоматически. Старую конфигурацию
   перед запуском требуется привести к текущему контракту.
5. Удалить неиспользуемые причины NONE, BATTERY_CHARGE и TEST_RUN.
   Отсутствие сессии уже представлено значением session=None; будущие режимы
   следует добавлять вместе с требованиями и реализацией.
6. Объединить продолжение TPC после подтверждённой изоляции обоих вводов.
   Условия подтверждения каждого контактора и сообщения об авариях остаются
   в отдельных методах; одинаковый выбор следующей цели находится в одном.
7. Объединить проверку безопасного источника ES, сохранив исключение для
   stop_generator: Grid relay ON независимо от наличия напряжения.
8. В ES-10 сослаться на общую последовательность ES-06 и повторный провал
   ES-07. В ES-08 исправить противоречие с уже реализованным HOLD: ручной
   Battery path сохраняется при запуске даже при доступной Grid.
   Cooldown в GC-07 исправлен с устаревших 300 на фактические 60 секунд.

## Что сохранено и почему

- Источник и силовой путь различаются: при Grid path ON и отсутствующей сети
  фактический источник BATTERY. Их объединение вернуло бы дефект реле Grid.
- Журнал и pending actions нужны для restart во время аппаратной операции.
  Отказ от старой совместимости не означает отказ от восстановления после
  сбоя текущей версии.
- Recovery отделён от обычного управления: он разрешает только ограниченный
  возврат и остановку своего разгруженного генератора.
- Контроллеры и HA adapter независимо проверяют физические предусловия.
  Это проверки на разных границах, а не случайное дублирование.
- Ручная сессия при доступной Grid не завершается автоматически; ручная
  outage-сессия завершается после устойчивого возврата Grid.
- Отказ генератора не вызывает автоматический запуск второго.
- Профили заслонки и температурные выдержки сохраняются: это описанное
  и проверяемое поведение GC, а не только заготовка будущих режимов.

старого A/B. Причина — прямое разрешение убрать совместимость.

Добавлены три случая отклонения старого журнала:
manual_generator_idle, returning_to_normal и журнал без контейнера supervisor.

Проверены полный pytest, компиляция Python и git diff --check.
Это программная регрессия; физические испытания в рамках ревью не выполнялись.
