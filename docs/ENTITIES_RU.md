# Home Assistant entities и команды — Energy ATS

Этот документ описывает фактический контракт между АВР и Home Assistant.

- физический смысл сигналов: `PHYSICAL_POWER_TOPOLOGY_RU.md`;
- нормативное поведение: `REQUIREMENTS_RU.md`;
- установка и обновление: `INSTALL_RU.md`;
- эксплуатационные настройки и пользовательские сообщения: `SETTINGS_RU.md`.

A/B — стабильные внутренние обозначения физических генераторов. Пользовательские имена, модели и паспортные мощности читаются отдельно и не меняют смысл A/B.

## Как в этом документе обозначается критичность

Критичность указывается непосредственно в разделах с сущностями:

- **КРИТИЧЕСКАЯ** — сигнал или исполнительное устройство непосредственно участвует в безопасном запуске генератора или силовом переключении. Неизвестное состояние может блокировать действие, а потеря подтверждения во время физической операции — привести АВР в состояние **«Требуется внимание технического специалиста»** (`recovery_required`).
- **ОБЯЗАТЕЛЬНАЯ** — сущность нужна для штатной конфигурации и принятия основных решений, но не является непосредственным подтверждением положения силового оборудования.
- **ВСПОМОГАТЕЛЬНАЯ** — используется только дополнительной функцией. Её отказ ограничивает эту функцию или включает консервативное поведение, но сам по себе не должен переводить основной АВР в `recovery_required`.
- **ДИАГНОСТИЧЕСКАЯ** — АВР публикует её для интерфейса, журнала и диагностики. Она не используется как управляющая обратная связь.

## 1. Вспомогательные переключатели Home Assistant

```text
input_boolean.automatic_generator_transfer
input_boolean.generator_test_mode
```

### `input_boolean.automatic_generator_transfer`

**Назначение: управляющая настройка, не физическая обратная связь.**

Разрешает автоматический запуск резервного питания после физического исчезновения сети. Ручная команда запуска генератора от этого переключателя не зависит.

### `input_boolean.generator_test_mode`

**Назначение: вспомогательная классификация внешнего запуска.**

Положительный маркер нового внешнего RUNNING как `TEST_RUN`. Сам переключатель не запускает и не останавливает генератор. Плановый пробный запуск АВР знает происхождение собственного запуска напрямую и не требует переключения этой сущности.

Если сущность отсутствует, это трактуется как `OFF`; если существующая сущность временно `unknown/unavailable`, её состояние считается неопределённым.

## 2. Входная сеть и основные силовые контакторы

**Критичность: КРИТИЧЕСКАЯ.** Эти сущности образуют основной контур безопасного силового переключения.

```text
binary_sensor.grid_input_ready
sensor.grid_input_state
binary_sensor.house_powered_by_grid
binary_sensor.house_powered_by_generator
switch.grid_power
switch.use_generator_as_power_source
```

Смысл:

- `grid_input_ready` — бинарный признак полной пригодности внешней сети: `ON` только когда все три фазы пригодны;
- `grid_input_state` — уточнение состояния входной сети: `normal` / `partial` / `lost`;
- `house_powered_by_grid` — обратная связь управляющей цепи основного сетевого контактора;
- `house_powered_by_generator` — обратная связь управляющей цепи основного генераторного контактора;
- `grid_power` — разрешение сетевой ветви;
- `use_generator_as_power_source` — выбор основной пары контакторов: `ON` — генератор, `OFF` — сеть.

Важно: `house_powered_by_*` находятся в управляющих цепях и не являются независимым силовым измерением после контактора.

Успешное выполнение команды Home Assistant не считается физическим подтверждением переключения. АВР ждёт соответствующий сигнал обратной связи.

`grid_input_state` разделяет качество внешней сети и положение силового пути:

- `normal` — все три фазы пригодны;
- `partial` — пригодна только часть фаз; например, одно реле напряжения временно отключило свою фазу;
- `lost` — пригодных фаз не осталось.

`partial` и `lost` сами по себе **не являются неисправностью контакторов и не требуют Recovery**. Они запускают обычную выдержку `grid_failure_delay`; если сеть не нормализовалась за это время, АВР начинает штатный переход на резерв.

Рекомендуемая Home Assistant template-сущность:

```yaml
- sensor:
    - name: "Grid Input State"
      unique_id: grid_input_state
      availability: >
        {{
          has_value('binary_sensor.grid_meter_status') and
          has_value('sensor.grid_l1_voltage') and
          has_value('sensor.grid_l2_voltage') and
          has_value('sensor.grid_l3_voltage')
        }}
      state: >
        {% set meter_ok = is_state('binary_sensor.grid_meter_status', 'on') %}
        {% set l1 = states('sensor.grid_l1_voltage') | float(0) > 160 %}
        {% set l2 = states('sensor.grid_l2_voltage') | float(0) > 160 %}
        {% set l3 = states('sensor.grid_l3_voltage') | float(0) > 160 %}
        {% if not meter_ok %}
          lost
        {% elif l1 and l2 and l3 %}
          normal
        {% elif not l1 and not l2 and not l3 %}
          lost
        {% else %}
          partial
        {% endif %}
```

Существующий `binary_sensor.grid_input_ready` остаётся входом «сеть полностью пригодна / не пригодна» и сохраняется для совместимости. Новый sensor нужен для различения частичной потери фаз и полного blackout; если он ещё не установлен, основная логика АВР продолжает работать по старому binary input.

## 3. Работа и дистанционный запуск генераторов

**Критичность: КРИТИЧЕСКАЯ для соответствующего генератора.** Без достоверных RUNNING/REMOTE АВР не может безопасно доказать успешный запуск или остановку.

Для A/B:

```text
binary_sensor.generator_a_is_running
binary_sensor.generator_b_is_running
switch.generator_a_remote_start
switch.generator_b_remote_start
```

`generator_*_is_running` — физическое подтверждение работы/наличия выхода генератора.

`generator_*_remote_start` — управляющий уровневый сигнал REMOTE. `ON` не доказывает успешный запуск, `OFF` не доказывает подтверждённую остановку.

Оба `*_is_running` могут одновременно быть `ON`. Это допустимо и не означает, что оба генератора одновременно подключены к общей генераторной шине.

### Управление воздушной заслонкой

**Критичность: КРИТИЧЕСКАЯ для автоматического запуска соответствующего генератора, если его алгоритм запуска требует заслонку.**

```text
button.generator_a_choke_to_cold_start
button.generator_a_choke_to_run
button.generator_b_choke_to_cold_start
button.generator_b_choke_to_run
```

`to_cold_start` переводит заслонку в положение холодного запуска, `to_run` — в рабочее положение.

## 4. Аварийный STOP и температура

```text
switch.generators_emergency_stop
sensor.garage_temperature
```

### `switch.generators_emergency_stop`

**Критичность: КРИТИЧЕСКАЯ.**

Аварийный STOP имеет приоритет над обычным управлением. Неизвестное состояние не считается безопасным разрешением на запуск.

### `sensor.garage_temperature`

**Критичность: ВСПОМОГАТЕЛЬНАЯ.**

Используется Generator Controller для выбора работы заслонки и времени прогрева. Временная недоступность температуры обрабатывается консервативно и сама по себе не блокирует основной АВР.

## 5. Имена, модели и основной генератор

```text
sensor.generator_a_name
sensor.generator_b_name
sensor.generator_a_model
sensor.generator_b_model
select.primary_generator
```

**Критичность:**

- `generator_a_name`, `generator_b_name`, `select.primary_generator` — **ОБЯЗАТЕЛЬНЫЕ** для корректного выбора и идентификации основного генератора;
- `generator_a_model`, `generator_b_model` — эксплуатационные метаданные; на силовое переключение напрямую не влияют.

Имена должны быть непустыми и различаться. `select.primary_generator` должен совпадать с одним из фактических имён генераторов и преобразуется АВР во внутренний A/B.

### Паспортные пределы мощности

```text
sensor.generator_a_nominal_power
sensor.generator_a_maximum_power
sensor.generator_b_nominal_power
sensor.generator_b_maximum_power
```

**Критичность: ВСПОМОГАТЕЛЬНАЯ.** Они обязательны только для автоматического управления некритичными нагрузками. Единицы — W.

Их отсутствие не должно нарушать основной алгоритм запуска/переключения; подсистема управления нагрузками переходит в локальное деградированное состояние.

## 6. Данные UPS и аккумуляторов

```text
sensor.ups_battery_charge_level_soc
sensor.ups_battery_time_remaining_minutes_ttg
binary_sensor.ups_running_on_battery
binary_sensor.ups_ready
```

**Критичность: ВСПОМОГАТЕЛЬНАЯ.** Используются только для отложенного запуска и циклической подзарядки.

Смысл:

- `ups_battery_charge_level_soc` — SoC 0–100 %;
- `ups_battery_time_remaining_minutes_ttg` — расчётное оставшееся время работы в минутах;
- `ups_running_on_battery` — `ON`, когда батарея реально разряжается; при заряде/поддержании должен быть `OFF`;
- `ups_ready` — способность UPS/АКБ продолжать работу, включая отсутствие критического состояния батареи.

Если функция работы от UPS выключена, эти сущности не влияют на обычную работу АВР.

При включённом отложенном запуске недостоверные или устаревшие данные прекращают ожидание и приводят к безопасному запуску генератора. TTG учитывается только при фактическом разряде.

## 7. Управление некритичными нагрузками

### Управляемые группы

```text
G1 = switch.non_critical_loads_first_floor
G2 = switch.non_critical_loads_basement_floor
```

**Критичность: ВСПОМОГАТЕЛЬНАЯ относительно основного АВР.** Ошибка G1/G2 ограничивает автоматическое управление нагрузками, но не должна сама по себе переводить силовой АВР в `recovery_required` или блокировать возврат на сеть.

Приоритет:

```text
возврат нагрузки: G1 -> G2
сброс нагрузки:   G2 -> G1
```

### Счётчик генераторной шины

```text
binary_sensor.generator_meter_status
sensor.generator_power
sensor.generator_current
sensor.generator_voltage
sensor.generator_apparent_power
sensor.generator_reactive_power
sensor.generator_power_factor
sensor.generator_frequency
```

**Критичность:**

- `generator_meter_status` и `generator_power` — **ВСПОМОГАТЕЛЬНЫЕ**, но необходимы для автоматических решений по нагрузке;
- ток, напряжение, полная/реактивная мощность, коэффициент мощности и частота — **ДИАГНОСТИЧЕСКИЕ** для АВР, если отдельным требованием не задано иное.

Для автоматического управления нагрузкой используется `sensor.generator_power`.

Отсутствие счётчика, `unknown/unavailable`, ошибка Modbus, ошибка G1/G2 или отсутствие пределов мощности не должны сами по себе создавать системное состояние `recovery_required`.

Если новые значения `sensor.generator_power` перестали обновляться, подсистема управления нагрузками считает измерение недостоверным и после восстановления требует нового периода стабилизации.

## 8. Присутствие семьи для планового пробного запуска

Сущность задаётся параметром:

```text
family_presence_entity
```

По умолчанию:

```text
group.family
```

**Критичность: ВСПОМОГАТЕЛЬНАЯ.** Не влияет на реальное резервное питание.

`unknown/unavailable` не блокирует основной АВР, но обычный плановый пробный запуск до принудительной даты требует достоверного подтверждения отсутствия семьи непосредственно перед REMOTE ON.

## 9. Команды приложения

АВР принимает:

```text
start_generator
stop_generator
reset
```

- `start_generator` — ручной управляемый запуск/переход на генератор;
- `stop_generator` — безопасное завершение управляемой работы от генератора;
- `reset` — попытка безопасного выхода из состояния **«Требуется внимание технического специалиста»** (`recovery_required`).

Команды не обходят проверки безопасности. При `armed=false` физические действия запрещены.

## 10. Основной датчик состояния АВР

```text
sensor.energy_ats_status
```

**Критичность: ДИАГНОСТИЧЕСКАЯ.** Это представление состояния АВР только для чтения; оно не используется как вход для силового управления.

### Состояние

Примеры человекочитаемого состояния:

```text
Ожидание данных
Проверка отсутствия сети
Питание от UPS
Запуск генератора
Переключение на генератор
Питание от генератора
Питание от внешнего генератора
Возврат на основную сеть
Переход на питание только от UPS
В доме работает только UPS линия
Требуется внимание технического специалиста
DISARMED — только наблюдение
```

`Требуется внимание технического специалиста` соответствует машинному состоянию `phase=recovery_required`.


## 13. Диагностика плановых пробных запусков

Атрибуты плановых пробных запусков в `sensor.energy_ats_status` — **ДИАГНОСТИЧЕСКИЕ**. Для каждого A/B публикуются:

- включена ли функция;
- последний достаточный по длительности запуск / исходная дата отсчёта;
- следующая дата, просрочка и дата принудительного запуска;
- состояние предварительного предупреждения;
- активная попытка и требуемая длительность;
- последний результат и причина неуспеха.

Это представление состояния, а не отдельный управляющий контракт.

## 14. Журнал и уведомления

События АВР публикуются в Home Assistant Logbook. Критические события дополнительно вызывают:

```text
script.notify_critical
```

Некоторые предупреждения управления нагрузками используют тот же путь уведомлений отдельно от уровня `CRITICAL`.

Журнал приложения содержит основной и подробный потоки событий, аппаратные команды и отправляемые сообщения. В основной Home Assistant Logbook публикуются только пользовательски значимые события; подробная техническая диагностика остаётся в журнале приложения.

Обычные публикации состояния, Logbook и уведомлений выполняются в фоне и не должны задерживать основной цикл управления на сетевой timeout.

Исключение — предупреждение перед принудительным плановым пробным запуском. Его доставка подтверждается синхронно: запуск не считается разрешённым, пока Home Assistant не подтвердил отправку уведомления.

Ошибка диагностической публикации сама по себе не должна менять физический источник питания или текущую управляемую сессию.

## 15. Краткая карта критичности

| Группа | Критичность | Что происходит при проблеме |
| --- | --- | --- |
| Доступность сети + обратная связь основных контакторов + силовые переключатели | **КРИТИЧЕСКАЯ** | АВР не имеет права угадывать положение силовой схемы; действие блокируется, а ошибка во время операции может привести к `recovery_required`. |
| RUNNING/REMOTE генераторов + аварийный STOP | **КРИТИЧЕСКАЯ** | Нельзя безопасно доказать запуск/остановку или разрешить новый запуск. |
| Команды заслонки | **КРИТИЧЕСКАЯ для автоматического запуска соответствующего генератора** | Запуск, требующий заслонку, не может быть выполнен штатно. |
| Имена генераторов и `select.primary_generator` | **ОБЯЗАТЕЛЬНАЯ** | Нарушается корректный выбор/идентификация генератора; это ошибка конфигурации, а не обратной связи контактора. |
| Данные UPS | **ВСПОМОГАТЕЛЬНАЯ** | Отложенный запуск/циклическая подзарядка ограничиваются; основной АВР сохраняется. |
| G1/G2, счётчик генератора, пределы мощности | **ВСПОМОГАТЕЛЬНАЯ** | Автоматическое управление нагрузками деградирует локально; основной АВР продолжает работу. |
| Присутствие семьи и температура гаража | **ВСПОМОГАТЕЛЬНАЯ** | Ограничивается соответствующая дополнительная логика; основной АВР продолжает работу. |
| `sensor.energy_ats_status` и его атрибуты | **ДИАГНОСТИЧЕСКАЯ** | Теряется часть интерфейса/диагностики, но не физическая обратная связь управления. |

## 16. Что намеренно отсутствует в контракте Home Assistant

АВР не моделирует как физический исполнительный механизм:

- отдельный контактор батареи / `connect_battery`;
- программный A/B selector общей генераторной шины;
- автоматический запрет второго RUNNING;
- отдельный силовой путь для пробного запуска;
- вспомогательный переключатель, который произвольно объявляет внешний генератор управляемым АВР;
- право подсистемы управления нагрузками управлять REMOTE, заслонкой или остановкой генератора.

Эти ограничения следуют из реальной физической схемы и требований проекта.
