## M2. Полный ручной цикл PRIMARY

**Результат:** PASS с некритичными замечаниями.

Фактическая последовательность:

- в 13:12:46 пользователь запросил резервное питание;
- Elemax запустился с управлением заслонкой, подтвердил RUNNING и завершил прогрев;
- перед transfer обе управляемые группы G1/G2 отключились;
- Grid path был подтверждённо разомкнут, затем дом перешёл через `UPS_ONLY` на Elemax;
- после команды возврата generator path был разомкнут, дом перешёл через `UPS_ONLY` на Grid;
- G1/G2 восстановились;
- после cooldown Elemax штатно остановился в 13:17:27.

Ожидаемый порядок `generator start -> warmup -> Generator supply -> Grid return -> cooldown -> generator stop` выполнен. Break-before-make и работа G1/G2 фактически подтверждены.

Некритичные замечания:

- App log не содержал сообщения о командах Generator Controller, Power Transfer и Load Manager, хотя должен быть полным диагностическим журналом;
- формулировки сообщений о запуске и остановке генератора звучали неестественно;
- отдельная привязка DETAIL-записей к `sensor.energy_ats_activity_detail` оказалась не нужна: подробная картина должна находиться в App log, а основной HA Logbook должен оставаться кратким.

Замечания исправляются в версии 1.0.6 в том же PR, где начат этот журнал результатов.

## M4. Grid debounce в обе стороны

### Часть A — краткая потеря Grid

**Результат:** PASS.

`binary_sensor.grid_input_ready` оставался `OFF` с 13:58:18,734 до 13:58:52,808 — около 34,1 с с учётом проверки сети реле напряжения. Это меньше рабочего `grid_failure_delay = 60 с`; ни один генератор не запускался, после восстановления Grid система вернулась в штатное состояние.

Замечание к пользовательскому статусу: после завершения базовой задержки и перехода UPS Run в `waiting_on_ups` App продолжал показывать «Ожидание запуска генератора», хотя запуск был отложен до отдельного условия UPS Run. В версии 1.0.7 статус уточняется до «Питание от UPS»; статус базовой задержки называется «Проверка отсутствия сети».

### Часть B — краткое возвращение Grid

**Результат:** PASS. M4 полностью пройден.

Во время устойчивой работы дома от Elemax `binary_sensor.grid_input_ready` перешёл в `ON` в 15:21:35,460, но снова стал `OFF` в 15:22:05,512 — примерно через 30,1 с. Это меньше `grid_restore_stable_time = 60 с`; дом остался на генераторе, возврат на сеть и остановка Elemax не начались.

После следующего появления Grid в 15:24:30,702 система дождалась полного стабильного интервала и начала возврат в 15:25:30,840.

## M5. Полный automatic outage и возврат Grid

**Результат:** PASS с некритичным замечанием к основному пользовательскому журналу.

Первый запуск сценария задержала включённая настройка Delayed Generator Start. После её изменения полный автоматический цикл прошёл штатно:

- после рабочей задержки 60 с автоматически запустился PRIMARY Вепрь;
- генератор прогрелся, G1/G2 отключились перед transfer, дом перешёл на Вепрь, затем обе группы восстановились;
- после возвращения и 60 с стабильной работы Grid дом перешёл через `UPS_ONLY` на основную сеть;
- Вепрь прошёл cooldown и штатно остановился.

Некритичное замечание: основной пользовательский журнал сообщал о начале возврата после 60 с стабильной Grid и затем об остановке генератора, но не показывал уже существующее физическое подтверждение «Подтверждено: дом питается от основной сети». В версии 1.0.7 это итоговое подтверждение публикуется и в основном журнале.

## M6. PRIMARY недоступен — физический fallback на SECONDARY

**Результат:** PASS без замечаний к силовой последовательности.

Тест одновременно проверил запуск после UPS Delayed Start по порогу SoC:

- после базовой задержки 60 с дом продолжил работу от UPS;
- при снижении SoC до настроенного порога 96% АВР начал автоматический запуск PRIMARY Вепрь;
- Вепрь не подтвердил RUNNING за 90 с, его REMOTE START был снят;
- АВР выполнил единственную fallback-попытку, запустил SECONDARY Elemax и после прогрева передал ему дом;
- G1/G2 штатно отключились перед transfer и затем восстановились;
- после устойчивого возвращения Grid дом вернулся на основную сеть, Elemax прошёл cooldown и остановился.

Таким образом, последовательность `Delayed Start -> Start SoC -> отказ PRIMARY -> SECONDARY -> Generator supply -> Grid return` физически подтверждена. Замечание только к отображению процентов: версия 1.0.6 показывала `96.0%`; начиная с 1.0.7 пользовательские сообщения показывают целые проценты без `.0`.
